# ADR-0005：引入最小 Web 工作台作为答辩展示交互层

- 状态：已接受（2026-08-30）
- 触发复审：答辩目标、后端 API 契约或前端产品范围发生实质变化时

## 背景

当前项目已经实现音频上传、异步转录、摘要、任务查询、转录下载和天气接口，但主要通过终端或 HTTP 客户端操作。答辩对象是老师，重点是汇报学习研究成果、技术决策和后续方向，而不是进行商业化产品展示。

需要增加一个低复杂度的浏览器交互层，使听众能够直观看到核心业务闭环，同时不把项目扩展成完整博客平台，也不让答辩依赖现场电脑的 Node.js、密钥、依赖安装或外部网络。

## 决策

- 在同一仓库中增加独立 `web/` 前端目录。
- 前端采用 React + Vite + TypeScript。
- 使用浏览器原生 `fetch` 调用现有 Express REST API；开发环境使用 Vite `/api` proxy。
- 使用 React 内置状态管理实现上传、Job 轮询、结果展示和天气查询；暂不引入 Redux、复杂服务端状态框架或大型 UI 组件库。
- 最小工作台只实现音频上传、Job 状态、摘要/转录结果、下载和天气查询。
- Web 工作台必须真实接入当前后端；现场实时启动不是硬性验收条件。
- PPT 是唯一正式答辩展示物，Web 画面、录屏、截图和架构图均作为 PPT 内嵌元素。
- 现场实时运行和离线 replay 都不是核心交付前置条件；离线 replay 仅作为后续可选备用方案。

## 备选方案

- **继续使用终端**：无需前端开发，但不利于老师快速理解用户使用方式，也无法充分体现全栈交互层。
- **原生 HTML/CSS/JavaScript**：依赖少，但随着上传状态、轮询和错误状态增加，维护性和类型安全较弱。
- **Vue + Vite + TypeScript**：可行，但当前项目没有 Vue 基础，无法提供明显收益。
- **Next.js**：功能更完整，但本项目已有独立 Express API，不需要 SSR、Server Actions 或复杂部署能力，会引入额外概念。
- **完整博客平台前端**：超出当前学习研究项目和答辩目标，违反 YAGNI。

## 后果

### 正面影响

- 用一个真实页面直观展示已有后端能力，形成后端核心 + Web 交互层的全栈项目雏形。
- 前后端统一使用 TypeScript，便于共享 DTO、状态和错误码语义。
- 不改变领域层、任务队列或 AI 适配器，前端可以独立迭代和回滚。
- PPT 可以同时呈现产品使用方式和技术实现证据。

### 代价与限制

- 增加前端依赖、构建脚本和联调工作。
- 浏览器实时调用仍受后端服务、OpenAI key 和网络影响；因此 PPT 不以现场实时调用为唯一证据。
- 当前工作台不是完整 CMS，不提供登录、任务历史、文章编辑、SEO 或发布能力。

## 不可做事项

- 不把静态 mock 或离线 replay 描述为实时服务能力。
- 不在前端保存 OpenAI key、服务器路径或内部异常堆栈。
- 不为了前端展示重写后端领域逻辑或提前固化全部长期维护任务。
