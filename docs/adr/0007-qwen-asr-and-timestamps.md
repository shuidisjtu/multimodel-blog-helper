# ADR-0007：转录上游切换为 Qwen-ASR（单 provider）与句级时间戳交付

- 状态：已接受（2026-09-25）
- 触发复审：DashScope 接口或接入域名再次变更、需要多 provider 容灾、时间戳粒度不满足实际需求时

## 背景

中转站的 `whisper-1` 已不可用（issue #16），项目**完全丧失转录能力**，因此本次改造的首要目标是恢复可用，而非叠加新能力。选型与实测过程见 [`docs/records/2026-09-23-qwen-asr-implementation-plan.md`](../records/2026-09-23-qwen-asr-implementation-plan.md) 与 [A6-1 证据](../evidence/a6-1-qwen-asr-feasibility/2026-09-25-a6-1-qwen-asr-feasibility-shuidisjtu.md)。

中期答辩要求「核心功能展示以**音频转录为带时间戳文本**和摘要生成为主」，故时间戳不是可选项；A6-1 实测证明最小改动路径同时满足时间戳需求，两者不再二选一。

## 决策

- **转录上游改为阿里云百炼（国内站）同步识别 `qwen-audio-3.1-asr-flash`**，一次 HTTP 调用（Node 内置 `fetch`），音频以 base64 Data URL 内联。**单 provider**：删除 `OpenAITranscriber`，不保留双实现（Whisper 已不可用，无对比评估价值）。
- **摘要模型保持 `gpt-4o` 不变**，不统一供应商。理由：切换需把 `responses.create` 改写为 `chat.completions.create`，与 [ADR-0001](0001-responses-api.md) 直接冲突，且会使 A5「Assistants API → Responses API 迁移」这一答辩点失效；而 `gpt-4o` 当前可用，切换零收益。
- **音频上限收敛到上游硬限之内**：`MAX_AUDIO_DURATION_SECONDS=300`、`MAX_UPLOAD_BYTES=15 MiB`。超限在**受理阶段**即拒，不让上游报错穿透（原 60 分钟 / 25 MiB 会让超限输入一路通过到转录才失败）。
- **句级时间戳由词级数据按标点重组**，**不采用上游返回的分段**。上游 `sentences[]` 是按静音切分的 VAD 片段，实测 171s 样本中最长一段 57.0s、含 12 个完整句子；按标点重组后为 31 句、时长中位 4.5s。重组是启发式，已知边界（标点稀疏、中英文标点集、极短片段）在 [`segment-builder.ts`](../../src/infrastructure/qwen/segment-builder.ts) 中逐条标注。
- **时间戳通过新增的独立端点交付**：`GET /api/v1/audio-jobs/{id}/transcript/timed`（`text/plain`，每行 `[mm:ss.xx → mm:ss.xx] 句子`）。**既有 `transcript.txt` 与 `GET .../transcript` 的内容与语义完全不变**——它们的契约已被 B5 契约测试与 B7 E2E 断言为「转录全文」，改为带时间戳会让「有无时间戳」两类任务产出不同格式的产物。
- **转录域与摘要域配置隔离**：转录只校验 `DASHSCOPE_API_KEY`，摘要只校验 `OPENAI_*`，缺失时各报自己的变量名。
- **接入域名**：`QWEN_ASR_ENDPOINT` 默认通用域名（开箱可用），正式/演示环境改用业务空间专属域名——DashScope 域名自 2026-09-30 起停止新特性，且其请求超时上限为 600 秒（专属域名 3600 秒）。

## 备选方案

- **异步文件转写（`...-filetrans`）**：时长上限 12 小时、适合长音频，但官方明确「仅接受公网音频文件 URL，不支持本地文件上传」。本项目音频存本地 `temp/`、单机部署无公网地址，采用它须引入音频公网托管（OSS 等），违背最小改动。
- **WebSocket 实时流式（`...-streaming`）**：可做实时字幕，但需实现完整会话、事件聚合与清理语义，代价显著高于同步接口，且本项目产品形态不需要实时性。
- **统一供应商（摘要也换成千问）**：见上「决策」第二条。
- **把时间戳写进既有 `transcript.txt`**：能以零新增路由满足「带时间戳文本」，但会破坏「下载即得转录全文」这一已被契约测试固定的不变式，且无时间戳任务需产出不同格式。故改为新增端点。

## 后果

- **转录能力不再依赖中转站**，`whisper-1` 失效不再影响核心功能；但引入对阿里云百炼的硬依赖，且**要求配置第二把密钥**（`DASHSCOPE_API_KEY`），缺失则启动失败。
- **base64 须整文件进内存**（与原先 `openAsBlob` 流式读取不同）。保护来自 15 MiB 上传上限与编码后 20 MiB 预检——两者都收敛在上游实测的 data-uri 上限内。
- **时间戳粒度受标点质量影响**：标点稀疏时片段会偏长（有意不臆造边界）。若实际样本显示粒度过粗，可再引入上游 VAD 边界作为二级切分信号（当前未实现）。
- **超限行为明确**：时长超 300s、上传超 15 MiB 分别返回 `AUDIO_TOO_LONG` / `FILE_TOO_LARGE`；上游同类错误码也映射为上述业务错误，不退化成泛化的 500。
- **实现状态**：本 ADR 记录的是已接受的决策。截至 2026-09-25，适配器、领域模型、时间戳重组与下载端点已落地；**组合根仍装配旧适配器**，切换与旧实现下线随 A6-5 完成——在那之前，真实任务的转录仍不可用，新端点对真实任务返回 `JOB_NOT_READY`。

## 触发复审的条件

- DashScope 接入域名或同步识别接口再次变更（含旧域名正式下线）；
- 需要多 provider 容灾或成本优化（届时 `Transcriber` 端口已就位，只需新增适配器 + 配置）；
- 时间戳粒度在实际样本上不可用，需引入 VAD 二级切分或调整重组阈值；
- 音频时长需求超过 300s（须改用异步 filetrans + 公网托管）。
