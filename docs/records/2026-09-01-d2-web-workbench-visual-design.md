# D2 Web 工作台视觉设计规范

> **版本**：v1.1 ｜ **日期**：2026-09-01 ｜ **状态**：实施中（D2 共享骨架、天气/DTO）  
> **视觉主题**：浅色博客助手（Light Blog Assistant）  
> **适用范围**：`web/` 当前已落地页面，以及后续接入音频模块时必须遵守的共享视觉合同。

本文是 D2 当前 Web 视觉实现的**唯一视觉事实源**。任何新增或替换组件，都应先按本文确定布局、颜色、尺寸、形状、状态和响应式行为，再编写 CSS。接口功能范围和测试边界见 [最小 Web 工作台实现设计](2026-08-30-web-workbench-design.md)；技术选型理由见 [ADR-0005](../adr/0005-web-workbench-for-defense-showcase.md)。

## 1. 设计定位、气质与边界

### 1.1 产品定位

页面面向课程答辩、学习研究和博客创作演示，不是商业 CMS，也不是后台管理系统。视觉应让观察者首先理解以下两条能力线：

1. **博客创作主线**：音频内容未来可整理为博客草稿；当前以音频任务槽位展示处理阶段。
2. **辅助工具主线**：地点天气查询已接入真实 `/api/v1/assistant/weather` 接口。

关键词：**浅色、留白、纸张感、编辑感、可靠、可解释、信息密度适中**。

### 1.2 视觉原则

- 使用浅灰蓝页面背景和白色内容卡片，模拟干净的博客编辑桌面。
- 使用蓝色表达主要操作和链接，使用蓝绿色表达工具/信息辅助，不将所有信息都做成高饱和色块。
- 状态颜色必须同时配合中文文案、边框或结构变化；禁止只用颜色表达成功、失败或待接入。
- 页面不加载远程字体、图片、图标、CDN 资源或外部样式；图形只用 CSS 和文本完成。
- 不显示密钥、服务器路径、上游服务原始消息、堆栈、临时文件名或内部异常对象。
- D2 当前音频区域是**可替换接入槽位**，不得让用户误以为上传、轮询、摘要或下载已经在本分支可用。

### 1.3 当前实现与后续接入边界

| 区域 | 当前状态 | 可见文案/行为 | 后续责任 |
| --- | --- | --- | --- |
| 顶部品牌区 | 已实现 | “多模态博客助手”及博客创作描述 | 共享，不应被音频模块重构 |
| API 状态条 | 已实现 | “API 通过本地 `/api` 代理接入” | 共享；如增加真实健康探测，需另行记录状态语义 |
| 音频任务区 | 仅视觉槽位 | “待接入”；展示 01–03 阶段 | 音频主流程负责人接入上传、Job 轮询、摘要/转录和下载 |
| 天气区 | 已接入 | 输入地点并查询真实天气 API | `ym-hello` 维护 DTO/API/错误文案 |
| 页脚 | 已实现 | 真实 API 优先及安全展示边界 | 共享 |

## 2. 页面画布与坐标规则

### 2.1 视口基准

- HTML 和 `body` 的最小宽度：`320px`。
- 目标最小移动端视口：`320px`；不得出现横向滚动条。
- 页面最小高度：`100vh`。
- 所有尺寸默认使用 CSS 像素（px）；字体尺寸使用 `rem` 或 `clamp()`。
- 全局使用 `box-sizing: border-box`，因此边框和内边距包含在声明的宽高内。
- 当前没有固定导航栏、抽屉、弹窗、浮层或 z-index 层；所有内容按普通文档流排列。

### 2.2 主容器

选择器：`.app-shell`

| 属性 | 值 | 说明 |
| --- | --- | --- |
| 宽度 | `min(1180px, calc(100% - 40px))` | 桌面最大内容宽度 1180px；普通视口左右各留 20px |
| 最小高度 | `100vh` | 内容不足时仍撑满视口 |
| 水平定位 | `margin: 0 auto` | 居中 |
| 顶部内边距 | `44px` | 桌面端顶部留白 |
| 底部内边距 | `28px` | 页脚后的安全留白 |
| 左右内边距 | `0` | 外侧留白由 width 公式提供 |

当视口宽度小于等于 `620px` 时，容器改为：

- 宽度：`min(100% - 28px, 1180px)`，即左右各 14px。
- 顶部内边距：`28px`。

### 2.3 页面层级与顺序

DOM 顺序必须保持如下顺序，视觉和键盘阅读顺序一致：

```text
main.app-shell
├── header.topbar
│   ├── 品牌文字组
│   │   ├── p.eyebrow
│   │   ├── h1
│   │   └── p.topbar-description
│   └── div.api-status
├── section.workbench-grid[aria-label="工作台模块"]
│   ├── section.panel.audio-slot
│   └── section.panel.weather-panel
└── footer.app-footer
```

桌面端视觉顺序为左侧音频、右侧天气；`880px` 以下视觉顺序变为天气在前、音频在后（通过 `.audio-slot { order: 2; }` 实现）。DOM 顺序仍保持音频在前、天气在后，保证源代码结构和键盘阅读顺序稳定；如果后续需要改变无障碍阅读优先级，应单独评审 DOM 顺序，而不能仅依赖 CSS `order`。

### 3.2 页面背景

`body` 使用两层背景，从上到下覆盖整个页面：

```css
radial-gradient(
  circle at 88% 0%,
  rgba(47, 124, 183, 0.10),
  transparent 28rem
),
linear-gradient(
  180deg,
  #F8FBFF 0%,
  #F4F7FB 62%,
  #EEF3F8 100%
)
```

- 径向高光位于页面右上角，中心点为水平 88%、垂直 0%。
- 径向高光颜色为半透明蓝 `rgba(47,124,183,0.10)`，最大半径 `28rem`，向透明渐隐。
- 线性底色顶部为 `#F8FBFF`，62% 处过渡到 `#F4F7FB`，底部为 `#EEF3F8`。
- 背景不得加入纹理、图片、噪点或深色大色块。

## 4. 字体、字阶与文本规则

### 4.1 字体

- 只使用系统字体，不下载远程字体。
- 中文默认使用 `Microsoft YaHei` 作为 Windows 优先回退；macOS/Linux 使用系统无衬线字体。
- 等宽字体仅用于机器可读或阶段识别信息，不用于长篇说明。
- 正文颜色为 `#17283D`；辅助文字颜色为 `#62748A`，不要使用纯黑 `#000000`。

## 5. 组件逐项设计规格

### 5.1 顶栏与品牌区

选择器：`.topbar`

- 位置：主容器顶部，位于卡片网格之前。
- 布局：`display:flex`，水平两端对齐，垂直居中。
- 子项间距：`gap:32px`。
- 下方间距：`margin-bottom:28px`。
- 左侧按顺序放置 eyebrow、主标题、说明；右侧放 API 状态条。
- 桌面端右侧状态条不得被压缩（`flex-shrink:0`）。

品牌区内容固定为：

```text
MULTIMODAL BLOG HELPER / BLOG ASSISTANT
多模态博客助手
把音频内容整理成博客草稿，并提供天气辅助信息
```

### 5.2 API 状态条

选择器：`.api-status`

| 属性 | 值 |
| --- | --- |
| 布局 | flex，垂直居中 |
| 子项间距 | `8px` |
| 内边距 | 上下 `10px`，左右 `12px` |
| 边框 | `1px solid #CFE0EE` |
| 形状 | `border-radius:999px`，胶囊 |
| 文字 | `#49647E`，`0.86rem` |
| 背景 | `rgba(255,255,255,0.82)` |
| 阴影 | `0 4px 12px rgba(44,78,112,0.07)` |

`.status-dot` 是 8px × 8px 的圆形绿色点，背景 `#247A52`，外圈使用 `0 0 0 4px rgba(36,122,82,0.12)`；点不承载唯一状态信息，旁边必须始终保留文本。

### 5.3 通用内容面板

选择器：`.panel`

- 作为音频和天气的共同卡片外壳。
- `min-width:0`，防止长文本撑破网格。
- 内边距：`clamp(22px, 4vw, 34px)`。
- 边框：`1px solid #D9E3EF`。
- 圆角：`16px`。
- 背景：`rgba(255,255,255,0.94)`。
- 阴影：`0 12px 32px rgba(39,68,101,0.10)`。
- 禁止使用厚重边框、渐变卡片、玻璃拟态或大面积装饰插图。

`.panel-heading` 使用 flex，两端对齐，子项间距 `16px`。标题组在左，模块状态标签在右。

### 5.4 模块眉题和状态标签

`.eyebrow` 是模块的英文识别眉题，颜色 `#138F91`，等宽字体、`0.72rem`、字重 `700`、字距 `0.12em`。

`.module-tag` 是胶囊状态标签：上下内边距 `5px`、左右 `9px`，圆角 `999px`，字号 `0.72rem`，等宽字体，禁止换行。

- 待接入：边框 `#E0BB7A`，文字 `#A96812`，背景 `#FFFAF1`。
- 已接入：边框 `#9BCDB5`，文字 `#247A52`，背景 `#F1FBF5`。

### 5.5 音频任务槽位

选择器：`.audio-slot`

标题固定为 `异步音频任务`，眉题为 `AUDIO PIPELINE`，状态为 `待接入`。槽位不能出现上传控件、假进度、假 Job ID、虚构转录内容或模拟成功结果。

#### 流程时间线

选择器：`.pipeline`

- 桌面布局：`1fr 42px 1fr 42px 1fr`。
- 三个阶段平均占据可用宽度；两个连接器各占 `42px`。
- 垂直居中。
- 上边距 `48px`，下边距 `28px`。
- 每个阶段卡片最小高度 `154px`，内边距上下 `22px`、左右 `16px`。
- 阶段卡片边框 `1px solid #DCE6F0`，背景 `#F8FBFF`，圆角 `9px`。
- 当前第一阶段 `.active` 边框为 `#8EB7D9`，内阴影 `inset 0 0 0 1px rgba(36,99,165,0.12)`。
- 阶段编号使用 `#2463A5` 等宽字体，编号下方间距 `24px`。
- 阶段副标题使用 `#62748A` 等宽字体。
- 阶段连接器为 1px 高的水平线，背景从 `#74A9D3` 渐变至 `#D6E3EF`。

三个阶段的固定内容：

| 编号 | 主标题 | 副标题 |
| --- | --- | --- |
| `01` | 上传受理 | 创建 Job |
| `02` | 异步转录 | 后台处理 |
| `03` | 摘要与下载 | 结果展示 |

#### 接入说明块

选择器：`.slot-note`

- 位于时间线下方。
- 内边距 `16px`。
- 左侧 3px 实线，颜色 `#D79A43`。
- 背景 `#FFF9EF`。
- 文字使用辅助色 `#62748A`。
- 两段文字最后一段无下边距。
- 固定语义：当前仅定义页面布局和状态视觉；真实功能由后续音频模块接入。

### 5.6 天气面板

选择器：`.weather-panel`

标题固定为 `地点天气查询`，眉题为 `WEATHER TOOL`，右侧标签为绿色 `已接入`。

面板标题下方说明：

> 使用现有天气 API 查询当前天气；服务端会校验地点并隐藏上游细节。

`.panel-intro` 上边距 `26px`、下边距 `20px`，行高 `1.65`，颜色 `#62748A`。

#### 地点表单

- 标签文字：`地点名称`。
- `label` 为块级元素，颜色 `#284662`，字重 `700`，下边距 `8px`。
- 输入和按钮在 `.input-row` 中横向排列，间距 `10px`，垂直居中。
- 输入框占据剩余宽度，`min-width:0`；按钮不收缩。
- 输入框内边距上下 `12px`、左右 `13px`；边框 `1px solid #B9CADC`；圆角 `9px`；背景 `#FFFFFF`；文字 `#17283D`。
- 输入框 hover 边框改为 `#78A6CE`。
- 输入框 `maxLength=200`；前端提示“最多 200 个字符；首尾空白由服务端标准化。”。
- 输入提交按钮内边距上下 `12px`、左右 `14px`；边框 `1px solid #2463A5`；圆角 `9px`；白色文字；字重 `800`；背景 `#2463A5`；阴影 `0 4px 10px rgba(36,99,165,0.18)`。
- 主按钮 hover：边框和背景均为 `#174F8C`。
- 加载时按钮文字为 `查询中…`，输入框和按钮均禁用。
- 空白或超长输入先在前端给出稳定提示，不发起请求；服务端仍是最终校验方。

#### 天气反馈区

选择器：`.weather-feedback`

- 位于表单后，顶部间距 `28px`。
- 最小高度 `176px`，保证 idle/loading/success/error 切换时卡片高度稳定。
- 内边距 `20px`。
- 边框 `1px solid #E0E8F0`，圆角 `9px`，背景 `#F8FBFE`。
- 使用 `aria-live="polite"` 和 `aria-atomic="true"`；错误内部使用 `role="alert"`。

四种主要反馈状态：

1. **默认 idle**：显示 `输入地点后发起一次真实 API 查询。`，颜色 `#62748A`，不显示结果或 requestId。
2. **加载 loading**：显示 `正在请求天气工具，请稍候。`，颜色 `#2463A5`；输入和主按钮禁用，不允许重复提交。
3. **成功 success**：使用 `.weather-result`，左侧 3px 绿色边框 `#247A52`，内侧左间距 `15px`。`.weather-reading` 横向排列，温度与地点信息间距 `16px`。温度为 `#174F8C`、`2.2rem`、字重 `800`、等宽；地点为 `1.1rem`；天气描述上边距 `4px`、颜色 `#62748A`。底部 requestId 上边距 `16px`。
4. **错误 error**：使用 `.weather-error`，左侧 3px 错误边框 `#C44F5A`，内侧左间距 `15px`；第一段错误文案颜色 `#A83F4A`。若服务返回 requestId，在错误文案下方显示等宽 requestId；地点非空时提供 `重试查询` 按钮。

#### 天气错误文案映射

| 后端情况 | 前端稳定文案 | 视觉/操作 |
| --- | --- | --- |
| `422 INVALID_LOCATION` | `请输入有效的地点名称。` | 错误边框，可修改输入后重试 |
| `503 WEATHER_UNAVAILABLE` | `天气服务暂时不可用，请稍后重试。` | 错误边框，保留地点，提供重试 |
| `429 RATE_LIMITED` 无 `Retry-After` | `天气查询请求过于频繁，请稍后再试。` | 错误边框，保留地点，提供重试 |
| `429 RATE_LIMITED` 有 `Retry-After` | `天气查询请求过于频繁，请在 N 秒后重试。` | 错误边框，N 为非负整数 |
| 网络错误 | `无法连接本地服务，请确认后端正在运行。` | 错误边框，不泄漏异常 |
| 未分类错误 | `天气查询暂时无法完成，请稍后重试。` | 错误边框，不展示原始响应体 |

`.retry-button` 是次级操作：上边距 `18px`，边框 `#C58937`，文字 `#8D5A11`，背景白色，无阴影；hover 背景 `#FFF7E8`。它不使用主蓝色，避免与首次查询操作混淆。

### 5.7 页脚

选择器：`.app-footer`

- 位于主网格下方，顶部间距 `24px`。
- 桌面端水平两端对齐，间距 `18px`，字体 `0.78rem`，颜色 `#62748A`。
- 左侧文字：`博客助手工作台 · 真实 API 优先`。
- 右侧文字：`不展示密钥、服务器路径或内部异常`。
- 页脚是说明信息，不使用边框、背景或阴影。

## 7. 交互状态、动效与可访问性

### 7.1 状态视觉规则

| 交互状态 | 输入 | 主按钮 | 反馈区 |
| --- | --- | --- | --- |
| 默认 | 可编辑，白底，`#B9CADC` 边框 | 蓝底“查询天气” | 中性提示 |
| 输入中 | 可编辑；最多 200 字符 | 可提交 | 不实时覆盖上一条已提交语义，提交后再更新 |
| 加载 | 禁用，透明度 `0.62` | 禁用，文字变为“查询中…” | 蓝色加载文案 |
| 成功 | 请求结束后可继续编辑 | 恢复可用 | 绿色左边框、天气读数、requestId |
| 可修正业务错误 | 保留原输入 | 恢复可用 | 珊瑚红左边框、稳定文案、重试 |
| 限流 | 保留原输入 | 恢复可用 | 稳定等待文案，可包含秒数 |
| 网络失败 | 保留原输入 | 恢复可用 | 不暴露异常，提供重试 |

### 7.2 焦点、键盘和语义

- `label[for]` 必须与天气输入 `id="weather-location"` 关联。
- 输入提示通过 `aria-describedby="weather-input-hint"` 关联。
- 反馈区使用 `aria-live="polite"`、`aria-atomic="true"`。
- 错误区域使用 `role="alert"`。
- `button:focus-visible` 和 `input:focus-visible` 使用 3px 高对比外轮廓、外偏移 3px：`outline:3px solid rgba(36,99,165,0.30)`。
- 不使用仅由颜色、动画或图标组成的状态提示。
- 禁用控件使用 `cursor:not-allowed` 和 `opacity:0.62`，文字仍须可读。

### 7.3 动效

当前页面不依赖必要动画。若后续添加过渡，只能用于状态切换、hover 或焦点反馈，且不得影响信息读取。`prefers-reduced-motion: reduce` 时：

- `scroll-behavior:auto`。
- 过渡时长 `0.01ms`。
- 动画时长 `0.01ms`，迭代次数为 `1`。
